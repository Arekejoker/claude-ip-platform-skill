# 故障排查（按症状查）

> 原则：先备份、后动手；一次只改一个变量；改完复验再继续。
> 每条的「实测」均来自 2026-10 我们自己的搭建过程，环境不同不一定复现。

## 1. 客户端连不上 / 出口 IP 不对

| 现象 | 排查 |
|---|---|
| 出口是机房 IP | 组选择错：查 `/proxies/US-Identity` 的 now；确认节点是 Residential 而不是 VPS-Relay |
| 出口是直连 IP | 规则没生效：查运行时规则表（API `/configs` 或 Verge 界面）是否有身份组置顶规则；Verge 的 prepend 写法已废弃，改用扩展脚本 |
| 完全连不上 | 先 `curl -x http://127.0.0.1:<端口> https://api.ipify.org` 看报错形态：拒连=本地端口/内核没起；超时=节点不通（跳 2/3） |
| 时好时坏 | 看是否被订阅更新覆盖（见第 4 条）；或晚高峰线路问题（见第 8 条） |

## 2. REALITY 握手失败（客户端超时 / 服务端日志报 invalid）

- **最常见原因（实测）**：伪装目标证书链超过 8KB 上限。Xray 26.x 用 `www.microsoft.com` 会触发（约 8273B）。换 `gateway.icloud.com`（约 3.2KB）解决。
- 其次核对五个参数逐字一致：flow、serverName、publicKey、shortId、端口。
- 自检命令：服务端 `xray -test -config ...`；看 `journalctl -u xray -n 50`。

## 3. 手机直连住宅代理不通（4G/5G 下）

- 实测：手机移动网直连住宅代理端口会连接错误/断连（固定宽带直连也可能不稳——跨境裸连本就脆弱）。
- 解法：手机节点加 `dialer-proxy: "VPS-Relay"`（经 VPS 中转）——**换路不换出口**，账号看到的仍是同一个住宅 IP。
- 注意选支持 dialer-proxy 的客户端（Stash / mihomo 内核的 CMFA、FlClash 均可）。

## 4. 订阅更新后链路消失（我们踩过的真实事故）

- 症状：某次订阅自动更新（每 12h）后，身份规则/节点全部消失，出口变回默认线路。
- 根因：Clash Verge Rev 已废弃 `prepend-*` 写法；且手工改的生成文件被订阅更新整份覆盖。
- 修复/预防：
  1. 用「扩展脚本」承载身份节点/组/规则（每次生成都重新注入）
  2. 或使用独立 profile，不跟订阅混在一起
  3. 每次改完/更新后，用运行时 API 复验（`/proxies` 里要有 US-Identity；规则表顶部有身份规则）

## 5. SSH 连不上

- 顺序错误是常见原因：**先部署密钥并验证成功，再轮换密码**；反过来可能把自己锁在外面。
- 连不上时用商家控制台的 VNC/串口兜底。
- 密码/密钥轮换后，确认新凭证可用再关旧会话。

## 6. 443 端口不通

1. VPS 本机：`ss -lntp | grep 443`（xray 在不在听）
2. 防火墙：`ufw status`（443 放行？）
3. 服务状态：`systemctl status xray`
4. 从外网测：客户端 `nc -vz <VPS_IP> 443` 或直接用客户端连一次

## 7. 支付/购买卡住

- USDT：用商家页面显示的**精确金额**转账，保存 txid 填回订单；TRC-20 手续费低
- 支付宝：走订单页跳转的官方通道，别扫来历不明的码
- 银行卡被拒：换通道（信用卡/USDT/PayPal），不要连续重试触发风控
- 所有价格与页面文案以现场为准

## 8. 速度慢 / 晚高峰抖

- 先确认大流量域名已排除（drive/photos 等走默认线路），别让身份链扛大流量
- 已做 BBR + MTU probing；仍慢可换 VPS 机房/线路再评估（成本是否值得由用户定）
- 身份链本身流量小（账号页面 + AI 对话），带宽不是瓶颈，稳定优先

## 9. 关于「账号被封」（重要）

- 本技能只负责出口 IP 这一环，**不承诺不被封**；封号因素还有支付、设备指纹、行为、内容等
- 如果用户遇到封号：不要在这条线上反复注册新号、不要换支付方式重试——先停下来，复盘环境，避免连坐更多资源
- 不提供绕过地区限制/KYC/多账号的任何操作指导
